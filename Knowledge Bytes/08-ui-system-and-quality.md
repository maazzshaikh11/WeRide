### Byte 8: The UI system, quality gates — and putting it all together
*Builds on:* Bytes 1–7 (this is how the screens are built and kept honest)

*In plain terms:*
All screens share one small **design system** — colour/spacing tokens, a single type scale, and a set of interaction primitives (buttons, cards, inputs) — so the app looks and feels consistent. A set of automated checks keeps behaviour and style from drifting.

*The code:*
```ts
// app/src/ui — every tappable thing is built from these
import { Button, PressableCard, TextField, FadeIn, Skeleton, haptic } from '../ui';
```
```ts
// app/src/theme/typography.ts — the one type scale (Fraunces for titles, Figtree for UI text)
title:  { fontFamily: WeRideFonts.heading, fontSize: 28, lineHeight: 34 },
body:   { fontFamily: WeRideFonts.body,    fontSize: 14, lineHeight: 20 },
```

*How it fits together:*
- **Tokens** live in `theme/theme.ts` (colours, spacing, radii, font names, owned by Person C); `typography.ts` turns them into text roles. A test enforces whole-number sizes, an 11 px floor and no `fontWeight` (weight comes from the font file).
- **Interaction primitives** (`app/src/ui`): `PressableScale` (press feedback + optional haptic), `PressableCard` (card that sinks and lights its border), `Button` (primary/secondary/ghost/danger with a size-stable loading state), `TextField` (animated focus, shake on a new error), `FadeIn`/`Skeleton` (entrance and loading). They use only opacity/transform on the native driver and respect the OS "reduce motion" setting.
- **Fonts** (`assets/fonts`) are static instances cut from variable fonts — React Native can't pick weights from a variable font. Each token's PostScript name must equal its file name; a test checks every token has a bundled file on iOS *and* Android.
- **Brand assets** (`assets/brand`): the logo as SVG, from which the app icons and the in-app logo PNG are generated by a script.
- **Quality gates:** each package runs *lint → typecheck → test* (CI, one job per package). App tests mock native modules at the boundary; the server uses Node's built-in test runner. `app/scripts/screenshots` renders real screens in a browser to regenerate the `screenshots/` folder.

## PUTTING IT TOGETHER

A rider signs in and opens a ride from the **Rides screen** (Byte 7), which resets the **shared stores** and enters the **app shell** (Byte 2). On the map, the **tracking module** fuses sensors into a verified position every second and publishes it (Byte 3); the app also feeds that position to its own route store. The position travels over the **live socket** to the crew while a throttled copy lands in **Firestore** (Byte 4). With a destination set, the rider's position becomes the origin for a **route/ETA request**, and the camera frames the result (Byte 5). Riders' hazard reports are clustered and shared, and an SOS is written locally first, then synced and pushed to the group even after a signal gap (Byte 6). Everything is drawn with one **design system** and guarded by automated checks (this byte), on top of a modular, contract-first structure (Byte 1).
